# Portal Hopper (RUN.world, Phaser 3)

Side-view platformer for kids. Portal Plaza (the hub) is a long hall of portals to 23 worlds: the original
Spooky Hollow, Moon Base and Frosty Peaks plus 20 worlds that each give the hopper a power (jetpack,
triple jump, pogo, super speed, swimming, giant, tiny, magnet, glide, air dash, wind, spring shoes,
flame shield, sugar rush, ghost mode, frog legs, bumper body, ground pound, beat jump, slow-mo).
Levels are ~13,000 units long with slides, springs, moving platforms, item boxes, boost pads, bumpers,
updrafts, a goal flag, and bad guys that only knock you back (bop them on the head to make them dizzy).
Ported from the prototype in `reference/portal-hopper.html` (brief: `reference/PORTAL_HOPPER_BRIEF.md`).

## Files

- **src/game/defs.ts**: every world (title, power, physics, theme colours, bad guys, treats, decor, music,
  section weights) and `ORDER` (portal order in the plaza and the "next world" chain).
- **src/game/levelgen.ts**: builds each layout from a library of sections with a fixed seed per world.
  Collectibles are saved by index, so changing a world's sections or seed resets that world's saved
  treats (bump the save key in save.ts if layouts change a lot). The original worlds keep their
  hand-made opening (`PREFIX`).
- **src/game/types.ts**: shared types, `GY` (ground line) and `LH`. **src/game/worlds.ts**: builds `WORLDS`.
- **src/scenes/PlayScene.ts**: physics and every power, collisions, bad guys, goal, portals, camera
  (follows up into the sky), rendering. In dev, `window.__ph` exposes the scene for test bots.
- **src/game/save.ts**: look, collected items and finished levels on `RundotGameAPI.appStorage` (key `save2`).
- **src/game/audio.ts**: per-world music (variations of four base songs), sfx, beat timing for the Disco Dome.
- **src/art/draw.ts** (prototype art, dispatch) and **src/art/draw2.ts** (new worlds' backgrounds, bad
  guys, treats, decor, level pieces, power effects). **src/art/sprites.ts**: PNG overrides listed in
  `public/sprites/sprites.json` (keys like `item-coin`, `enemy-slime`, `hat-crown`, `decor-palm`, `player-body`).
- **src/ui.ts** + **index.html** + **src/style.css**: DOM HUD (world, treats, power), title card,
  wardrobe, touch buttons, keyboard.
- No localStorage: use the SDK storage APIs.

## Template notes (RUN Phaser template)

## File Structure (as-shipped)

- **src/main.ts** — Entry point. Creates Phaser.Game instance (config: scene, physics arcade, scale FIT). Uses RundotGameAPI for logging. No explicit SDK init; SDK is used after game is created.
- **src/scenes/HelloWorldScene.ts** — Default scene. Replace or extend for your game. Shows CDN asset loading, physics, and pointer input.
- **src/style.css** — Global styles.
- **index.html** — Mount point `#app` for Phaser; optional `#dialog-overlay` for HTML overlays (e.g. dialogs). Script entry: `/src/main.ts`.
- **public/** — Small static assets; referenced via relative paths or loaded in preload().
- **public/cdn-assets/** — Large assets deployed to CDN. Load at runtime via `RundotGameAPI.cdn.fetchAsset('filename.png')`, then feed blob URL to `this.load.image()` and `this.load.start()`.
- **vite.config.ts** — Vite + `rundotGameLibrariesPlugin()`. Build target es2022 (SDK uses top-level await).
- **game.config.json** — Generated by `rundot init`. Do not edit manually.

## Key Patterns

- **Game loop** — Managed by Phaser. Add logic in the scene’s `update()` method.
- **Input** — Use Phaser input: `this.input.on('pointerdown', ...)` or `gameObject.on('pointerdown', ...)`. For overlay UI (e.g. dialog close), DOM (`document.getElementById`, `addEventListener`) is acceptable.
- **Assets** — In-scene: load in `preload()`, use in `create()`. CDN: `const blob = await RundotGameAPI.cdn.fetchAsset('name.png')`, `URL.createObjectURL(blob)`, load into Phaser, then `URL.revokeObjectURL(blobUrl)` in loader `complete` callback; call `this.load.start()` after queueing.
- **RundotGameAPI** — Import from `@series-inc/rundot-game-sdk/api`. Use `RundotGameAPI.log()` for debug in RUN.game host; `RundotGameAPI.cdn.fetchAsset()` for CDN assets. No separate init step in main.
- **Scenes** — Extend `Phaser.Scene`, pass to `scene: [MyScene]` in game config in main.ts. Use `super("scene-key")` in constructor.

## What to Modify

- **New game logic** → New scene in `src/scenes/`, add to `scene` array in main.ts config.
- **New small assets** → Add to `public/`, load in scene’s `preload()`.
- **New large/CDN assets** → Add to `public/cdn-assets/`, load at runtime with `RundotGameAPI.cdn.fetchAsset()` and the loader pattern above.
- **Game config (resolution, physics)** → Phaser.Game config in main.ts.
- **Overlay UI** → Add markup in index.html, show/hide via DOM in the scene (e.g. classList add/remove).


## F12 Games

This game is also on F12 Games (https://games.f12crowd.com/games/portal-hopper/), built with `npm run build:pwa`
(the RUN SDK is swapped for `../f12-games/platform/run-shim.ts`).
- Release to F12 with `npm run release -- --pwa`; a `rundot deploy` that Claude runs also updates F12 (hook).
- After adding a new RundotGameAPI call, run `node ../f12-games/tools/check-sdk.mjs .` and fill any gap in the shim.
